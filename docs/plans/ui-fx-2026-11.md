## 0. The ask

The owner's request, restated:

- **Animated wrappers for standard components.** Wrap the React and React Native components used to
  build high-end apps, such as Button, FlatList, Tooltip, Toast/PopUp and Modal, so that they animate
  from one codebase on iOS, Android and the web.
- **Three preset families, each "in" and "out":**
  1. **Breakup / dispersal.** On interaction the element shatters or disintegrates. Fragment
     density runs from broken glass down to sand, and the physics are configurable.
  2. **Slide-to.** The element slides in a direction, or along a path the developer defines.
  3. **Fade.** Plain fades, plus "emerge from shadow" with a configurable entry angle and the kind of
     control professional animation software gives.
- **Configurable and composable.** Every preset is fully configurable, reusable, and can be combined
  into custom sequences.
- **Build on existing components.** Extend the existing components with animation parameters instead
  of reinventing them.
- **Naming.** Recommend a component naming scheme (`FlareButton`, `FButton`, or something else).

## 1. Recommendation on one screen

- **Two rendering techniques behind one API, chosen per preset.**
  - **Live:** animate the real view (transform, opacity, filter, gradient overlay) on the UI thread
    with Reanimated shared values. This covers slide, slide along a path, fade, the cheap "emerge"
    variant and press feedback. It needs no snapshot and no Skia.
  - **Snapshot:** capture the view to an image, hide the real view, and play the effect in one
    shared Skia overlay canvas at the app root, also on the UI thread. This covers shatter,
    disintegrate, dust, the shader "emerge", and assemble-in.
- **On the web, both hosts share one driver** (§6.11):
  - **Live presets** become Web Animations API keyframes sampled from the same closed-form pose, so
    transform and opacity run on the browser's compositor thread.
  - **Snapshot effects** draw straight into CanvasKit through `@flare-engine/render-web`, with reusable
    `Float32Array` buffers.
  - react-native-web and plain React DOM differ only in how the host element is reached.
- **Flare owns the enter/exit lifecycle** (presence plus an awaited exit). It does not build on
  Reanimated custom layout animations, which are native-only (§3.2), or on View Transitions, which
  are DOM-only and cannot shatter (§3.8).
- **One new package, `@flare-engine/ui-fx`, at tier 4.** It moved from 3.5 because the web snapshot
  path reuses `@flare-engine/render-web` (call C26). It has four entry points:
  - `.`: React Native components and the live runtime, for native and react-native-web
  - `./dom`: React DOM components, with no React Native import
  - `./core`: headless maths that `bun test` can run
  - `./fx`: the snapshot host. Conditional exports give native builds the RN-Skia host and web
    builds the CanvasKit host. Everything Skia-related is an optional peer, and on the web it loads
    lazily.
- **Naming:** a `FlareButton`-style prefix plus a `createFlareComponent(Component)` factory. Presets
  are plain factories: `shatter()`, `disintegrate()`, `slide()`, `fade()`, `emerge()`. `FButton` has
  no precedent anywhere in the ecosystem read (§6.2).
- **Motion model:** closed-form trajectories, which are deterministic, scrubbable and exactly
  reversible, organised into the four parameter blocks After Effects uses: fragment, force, release,
  physics (§7).
- **Order of work:**
  1. Gate 0 spikes measured on device
  2. headless core
  3. live presets and presence
  4. the FX host and snapshot effects
  5. components (lists, toast, tooltip, modal)
  6. benchmarks and docs

### 2.2 Gaps

- No engine component animates a live RN view, and nothing implements presence (keeping an exiting
  element alive until its exit finishes).
- No RN view is ever snapshotted. `makeImageFromView` is used nowhere in `packages/**`.
- There is no Toast and no Tooltip. `List` is not a `FlatList`, and `Modal` has no animation.
- The renderer abstraction cannot draw polygons (`drawVertices`) or clip.
- There is no arc-length parameterisation of curves.
- There is no OS reduced-motion bridge.

### 2.3 Constraints that bind the design

- **Threading. ADR-0001 says the engine has no Reanimated animation API anywhere and animates on the
  JS thread** ([adr-0001](../design/adr-0001-renderer-and-threading.md) §2, row "Animation").
  - That decision describes the game runtime.
  - ui-fx animates host-app UI at exactly the moment the JS thread is busiest: deleting a row
    re-renders React on that same thread. That is why §5 recommends the UI thread.
  - ADRs are for breaking changes ([adr-0000-template.md](../design/adr-0000-template.md)), and a new
    package is additive. This plan therefore proposes a one-line scope note in ADR-0001, not a new
    ADR (call C16).
  - ADR files are a held path, so that note is a held edit.
- **Tiers.** The dependency rule is in `AGENTS.md`, and `LAYER_MAP` is in
  `scripts/check-deps-tiers.mjs:37-67`, a held path. ui-fx is tier 4 (C26), so it may depend on
  `math` (0), `a11y` (2.5), `animation` (3) and `render-web` (4).
- **A new package needs a named consumer and a design** ([roadmap.md](roadmap.md#epics), #182).
- **Lockstep publishing.** The 42 packages publish together through npm Trusted Publishing. A package
  missing its trusted-publisher entry fails with `ENEEDAUTH` (`AGENTS.md`). The first publish of a
  new name is therefore an owner action (§10, D7).
- **Stability tiers.** A new package enters **Beta** ("tested, no consumer yet") until an
  owner-operated consumer imports it
  ([versioning-and-announcements.md](versioning-and-announcements.md#stability-tiers)).
- **House rules.** Zero allocation in per-frame paths, `Float32Array` for bulk data, no classes, named
  exports, no `export *` outside `engine`.
- **Perf freshness.** An edit to a tier-0/1 package (`math`, `core`, `ecs`) stales every bench lane, and
  the Android lane needs the phone. New maths therefore stays in `ui-fx/core` first (call C14).

### 3.2 Reanimated 4.7 and worklets 0.13

All from the [Reanimated docs](https://docs.swmansion.com/react-native-reanimated/docs) and the 4.7.1
source unless noted.

**Layout animations: what works where**

- Predefined `entering`/`exiting`, `Keyframe`, layout transitions and `itemLayoutAnimation` run on
  Android, iOS and the web.
  - The presets are Fade, Bounce, Flip, LightSpeed, Pinwheel, Roll, Rotate, Slide, Stretch and Zoom.
    None of them is a shatter, a path slide, or an angled reveal.
  - Spring modifiers (`.springify()`) are **not supported on the web**: "Spring-based animations are
    yet to be introduced to the web."
- **Custom entering/exiting/layout worklet functions are Android and iOS only.** On the web the
  runtime logs "supports only predefined animations" and does nothing (`layoutReanimation/web/animationsManager.ts:52-63`).
- `Keyframe` is the only custom-shaped enter/exit that runs on all three platforms. On the web it
  compiles to a CSS keyframes rule. Keyframe 0 is required, and the transform order must stay the
  same across keyframes.

**How exit works**

- Native, 4.7: a new layout-animation engine is the default. "Exiting views stay at their host
  position" ([4.7.0 notes](https://github.com/software-mansion/react-native-reanimated/releases/tag/4.7.0)).
  - Whether touches still reach an exiting view, and how nested exits are ordered, is undocumented. `[U]`
- Web: on unmount, Reanimated shallow-clones the element and **moves the real children into the
  clone**. It appends the clone to `offsetParent` with absolute positioning, runs CSS, then removes
  it. The clone has no React handlers.
- **Under reduced motion, exits are omitted entirely** and entering jumps to its end.
  - `ReduceMotion.System` is the default.
  - `useReducedMotion()` reads the setting **once at app start**.
  - `ReducedMotionConfig` is global, so a library must never mount it
    ([accessibility](https://docs.swmansion.com/react-native-reanimated/docs/guides/accessibility/)).

**CSS animations, transitions and pseudo-selectors**

- CSS animations and transitions run on all three platforms, and **there is no CSS exit**: unmount
  cancels the animation. Callbacks fire on native from 4.6.
- Pseudo-selectors (`:hover`, `:active`, `:active-deepest`, `:focus`, `:focus-within`) attach native
  recognisers, need no re-render and no gesture library, and work on all three platforms from about
  4.6. `[U: exact first version]`
  - An iOS view at or below 1% opacity receives no input.
  - Timing comes from the top-level `transition*` properties.

**Limits and rules for a library**

- Performance guidance: about 100 animated components on low-end Android and 500 on iOS. Beyond that,
  "consider using Reanimated with react-native-skia"
  ([performance](https://docs.swmansion.com/react-native-reanimated/docs/guides/performance/)). This is
  why shards are never N animated Views.
- **Lists:**
  - `Animated.FlatList`'s `itemLayoutAnimation` is single-column only.
  - The user-facing `CellRendererComponent` is typed `never`.
  - `skipEnteringExitingAnimations` covers only list mount and unmount.
- **Worklets:**
  - `runOnUI`/`runOnJS` are deprecated in favour of `scheduleOnUI(fn, ...args)` /
    `scheduleOnRN(fn, ...args)`.
  - A library must ship **untransformed** worklets; pre-transformed ones cause the documented
    plugin-version-mismatch error ([troubleshooting](https://docs.swmansion.com/react-native-worklets/docs)).
  - Worklets 0.13 stores closures as arrays, no longer workletizes getters, setters or constructors,
    and removes implicit `this` context capture.
  - Bundle Mode is opt-in by the app and Legacy Eval is still the default. A library's worklets must
    be self-contained to work in both modes without consumer `importForwarding` config
    ([bundle mode](https://docs.swmansion.com/react-native-worklets/docs/bundleMode/)).
- **4.7 breaking items relevant here:** `measure` on an unmounted ref returns `null`, so ui-fx must
  measure before unmount and always null-check. `AnimatedRefOnUI` is read with `.value`.
- **Feature floors:**
  - `.withTargetValues()` and flat transform values need 4.4.
  - Pseudo-selectors and native CSS callbacks need 4.6, which means RN 0.83 or later.
  - The new exit engine needs 4.7, which means RN 0.86 or later and worklets 0.13.

### 3.3 RN-Skia 2.14 (scoped) and the v3 horizon

Read from the source at tag `v2.14.0` (<https://github.com/wcandillon/react-native-skia/blob/v2.14.0>),
the v3 docs at `v3.10.2`, and the `canvaskit-wasm@0.41.0` typings.

**`makeImageFromView(ref, callback?)`**

- It is **always async**: a JS-to-main-thread round trip that returns a CPU raster `SkImage` in
  device pixels. Source: `packages/skia/src/skia/core/Image.ts:27-55`.
- It needs `collapsable={false}` on the root.
- On **Android** it walks the tree into a **software** `ARGB_8888` bitmap.
  - Children that are not visible are skipped, and opacity is multiplied down the tree.
  - TextureView children are read with `getBitmap`; SurfaceView children with `PixelCopy` behind a
    5 s main-thread latch.
  - Source: `android/.../ViewScreenshotService.java`.
  - Elevation shadows, hardware bitmaps and blur may be missing. `[U: device]`
- On **iOS** it uses `drawViewHierarchyInRect:afterScreenUpdates:YES`.
- **There is no web implementation.**
  - The web path only calls a caller-supplied callback.
  - The built-in `MakeImageFromViewTag` is a stub that resolves `null`
    (`web/JsiSkImageFactory.ts:27`).
  - The v3 docs say to rasterise the DOM yourself and pass the canvas to `MakeImageFromNativeBuffer`,
    which v2 web already accepts (`:34-70`).
- **v3 removes `makeImageFromView`.** The replacement is React Native WebGPU's
  `drawElementImageToTexture` plus `Skia.Image.MakeFromGPUTexture`
  ([v3 snapshot-views](https://github.com/wcandillon/react-native-skia/blob/v3.10.2/apps/docs/docs/snapshot-views.md)).

**Drawing many fragments**

- `<Atlas image sprites transforms colors colorBlendMode>` issues one `drawAtlas` call.
  - RSXform covers uniform scale, rotation and translation only.
  - Sprites are **rectangles**.
  - `colorBlendMode` defaults to `dstOver`.
- `useRSXformBuffer` / `useRectBuffer` / `useColorBuffer` mutate host objects in place on the UI
  thread with no React re-render. Native still reads the arrays element by element every frame
  (inference from `cpp/api/recorder/Drawings.h`).
- `<Vertices>` supports texture coordinates through an `ImageShader` on the paint.
  - In 2.14 the vertices are `SkPoint[]` only, and `SkVertices` is rebuilt every draw.
  - `Float32Array` vertices exist in v3 only.
- **Any Skia prop accepts a shared value** (transforms, vertices, uniforms, image, picture) from
  RN-Skia 2.10 with Reanimated 4.

**Shaders**

- `<Shader source uniforms>` with an `<ImageShader>` child works on native and the web, through
  CanvasKit `makeShaderWithChildren`.
- **The `<RuntimeShader>` image filter throws "not implemented" on the web** in 2.14.0, and still in
  3.10.2 (`web/JsiSkia.ts:54`), although the docs' web-unsupported list omits it. Dissolves must
  therefore be `<Shader>` plus `<ImageShader>`.

**Overlays**

- **Android:** a non-opaque canvas uses TextureView by default. Z-order and alpha behave correctly,
  at the cost of one extra copy and about a frame of latency.
  `android={{ surfaceType: "SurfaceView", zOrderOnTop: true }}` draws above every RN view, including
  navigation screens. Source:
  [canvas.md](https://github.com/wcandillon/react-native-skia/blob/v2.14.0/apps/docs/docs/canvas/canvas.md).
- **iOS:** the canvas is a `CAMetalLayer` and behaves like any other view.
- `pointerEvents="none"` works on a Canvas.

**Web**

- CanvasKit is **2.9 MB gzipped** and loads asynchronously, through `LoadSkiaWeb` or `WithSkiaWeb`.
- In 2.14.0 **every `<Canvas>` and every `Surface.MakeOffscreen` owns its own WebGL context**, and
  Chrome caps a page at 16 live contexts, evicting the oldest.
  - The shared-context fix shipped in 2.15.3, which exists **only in unscoped `react-native-skia`**
    ([2.15.3](https://github.com/wcandillon/react-native-skia/releases/tag/v2.15.3)).
  - So ui-fx must use one shared overlay canvas.
- The RN-Skia web `drawAtlas` wrapper allocates on every call (`web/JsiSkCanvas.ts:412`). Direct
  CanvasKit accepts reusable `Float32Array` or `Malloc` buffers.

**v3 notes (forward compatibility only)**

- Graphite renders on Metal and Vulkan; v3 needs Android API 26 with Vulkan 1.1 and a development
  build (no Expo Go).
- Atlas becomes a single `drawVertices`. `ShapeBlob` is fill-only, so it cannot carry textured
  fragments.
- `encodeToBytes` / `readPixels` become async.

### 3.4 React Native core inventory (0.88)

- **Deprecated:** ImageBackground, SafeAreaView, InputAccessoryView, DrawerLayoutAndroid
  ([components](https://reactnative.dev/docs/components-and-apis)).
- **Touchables are discouraged but not deprecated.** `Button` is minimal: "build your own button using
  Pressable" ([button](https://reactnative.dev/docs/button)). FlareButton therefore wraps
  **Pressable**.
- **There is no Toast in core**, only `ToastAndroid`, whose gravity is ignored from Android 11. There
  is no Tooltip.
- **Refs are DOM-like element nodes since 0.82**, with `getBoundingClientRect()`. `measure` and
  `measureInWindow` are labelled legacy ([element nodes](https://reactnative.dev/docs/element-nodes)).
- New Architecture layout is synchronous in `useLayoutEffect`. The architecture page's own example is
  a tooltip that measures and positions itself in one commit
  ([architecture](https://reactnative.dev/architecture/landing-page)).
- `Modal` offers only `none | slide | fade`. Nothing outside a Modal can draw over it
  ([modal](https://reactnative.dev/docs/modal)).

### 3.5 Lists

- **FlashList v2** is New-Architecture only and has no native code.
  - It **recycles** cells: a cell is re-rendered with a different `item` without mounting, so
    mount-bound enter and exit do not fire.
  - Shared values must be reset when the item id changes.
  - Call `prepareForLayoutAnimationRender()` before an animated insert or delete.
  - Sources: [recycling](https://shopify.github.io/flash-list/docs/recycling),
    [reanimated guide](https://shopify.github.io/flash-list/docs/guides/reanimated).
- **Legend List 3.7.2** is pure TypeScript, and `recycleItems` defaults to `false`.
  `AnimatedLegendList` with `itemLayoutAnimation` works on RN Web
  ([docs](https://legendapp.com/open-source/list/v3/react-native/keyboard-and-animated/)). Its New
  Architecture requirement is unknown. `[U]`
- **Consequence:** the list primitive must be **a row keyed on item identity**, not a list wrapper.
  - Enter fires when a key first appears in the data, not when a cell mounts.
  - Exit is driven by the data: the row leaves, the effect plays, then the row is removed.

### 3.7 Toasts and tooltips

- **Toasts have converged on Sonner's shape:** a global `toast()` plus one `<Toaster/>`, configured by
  `position`, `visibleToasts` (3), `gap` (14), `offset`, `swipeDirections`
  ([sonner](https://sonner.emilkowal.ski/toaster)).
  - Tamagui v3 dropped its provider API for this shape ([tamagui](https://tamagui.dev/ui/toast)).
  - sonner-native needs six native peers and advises against web use.
  - react-native-notifier contributes queue modes `reset | standby | next | immediate`.
- **Tooltips:**
  - `@floating-ui/core` is platform-agnostic placement maths; `@floating-ui/react-native` 0.10.10 is

### 3.9 Prior art for the shatter and dust look

- **Telegram Android, "ThanosEffect"**
  ([source](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/ui/Components/ThanosEffect.java)):

### 3.10 Professional parameter vocabularies

**After Effects Shatter** (CS4 manual mirror, pp. 582-584; `helpx.adobe.com` returned 403)

- It splits into four blocks:
  - **Shape:** pattern, repetitions, direction, origin, extrusion
  - **Force 1/2:** position, depth, radius, strength
  - **Gradient:** a luminance layer sets release order
  - **Physics:** rotation speed, tumble axis, randomness, viscosity, mass variance (default 30%),
    gravity, gravity direction and inclination
- The timing idiom is "animate the Radius, not the Strength", which means a moving release front.
- Its pieces fly through each other.

**Wipes and shadows**

- Linear Wipe's angle is the **direction of travel**, so 90° runs left to right.
- Gradient Wipe's Transition Softness is the model for a soft reveal edge.
- Drop Shadow: direction, distance, softness, opacity.

**Fracture tools**

- **Blender Cell Fracture** (addon source): `source_noise`, `cell_scale` (anisotropy), `recursion`
  with "near cursor" or "small" selection, and `margin`.
- **Cinema 4D point generator**: Uniform, Normal, Inverse Normal or Exponential distributions;
  standard deviation 0.01-0.70; 2-200,000 points; a seed
  ([maxon](https://help.maxon.net/c4d/en-us/Content/html/OPOINTCREATOR_PANEL-ID_POINTCREATOR_CREATEPOINTSTAB.html.md)).

**Springs and easing**

- Apple (WWDC23) and Motion both moved to **duration + bounce** springs: bounce 0 is the default,
  0.15 is subtle and 0.3 is noticeable ([wwdc](https://developer.apple.com/videos/play/wwdc2023/10158/)).
  The exact negative-bounce damping formula is `[U]`.
- GSAP MotionPath and After Effects agree that rotation follows the path's **tangent**, not its
  velocity; AE's Orient Along Path flips on overshoot.

### 3.11 Algorithms (sources in §3.10 and the local notes)

- **Fracture:**
  - The jittered grid and triangle grid are O(n), have static index layouts, and give rectangles that
    `drawAtlas` can draw directly.
  - Radial glass is rays plus geometric rings around the impact point, clipped to the rectangle, at
    O(R·K) per trigger.
  - Voronoi through Delaunator is ISC-licensed and does 100k points in 82 ms on a 2017 laptop
    ([repo](https://github.com/mapbox/delaunator)). That makes it a per-trigger cost, not a per-frame
    one; the Hermes cost is `[U]`.
- **Geometry is cached in normalised space**, keyed by pattern, seed and aspect ratio. Only the
  snapshot is per trigger.
- **Closed-form motion with linear drag k and gravity g:**
  `x(t) = x0 + (g/k)t + (v0 − g/k)(1 − e^(−kt))/k`.
  - It is deterministic, frame-rate independent, scrubbable, and exactly reversible for assemble-in.
  - A fixed-timestep accumulator is needed only when collisions are on.
- **Path slide:** a cumulative-distance lookup table per path. Easing applies to distance, and
  rotation comes from the tangent ([pomax](https://pomax.github.io/bezierinfo/#tracing)).
- **Determinism:** use an integer-state PRNG with one stream per concern. Trigonometry is not
  bit-identical across JS engines, so goldens compare with a tolerance.

## 5. Approaches considered

**A. Hybrid: live presets on Reanimated, snapshot effects in one Skia overlay, all on the UI thread. (Recommended)**

How it works:

- Live presets drive the real view through shared values.
- Snapshot presets capture once on the JS thread. Fracture and per-fragment initial data are
  generated once, then handed to UI-thread worklets.
- The worklets evaluate the closed-form motion into `<Atlas>` buffers every frame.

Trade-offs:

- It is the only option that does not jank when the host app re-renders at the moment the effect
  fires (deleting a row, closing a toast).
- On the web the "UI thread" is the main thread anyway, so the behaviour converges.
- It costs a departure from ADR-0001's "no Reanimated animation API anywhere" for this package, and a
  second execution context to test.

**B. Engine loop: everything through `GameLoop`, `FrameRenderer` and `SpriteBatch` on the JS thread.**

- **For:** it is consistent with ADR-0001 and reuses `particles` and `render-web`.
- **Against:**
  - The JS thread is busiest exactly when these effects fire.
  - Every frame pays for recording a picture plus the UI-thread texture handoff (`game-view.tsx:61`).
  - Fading fragments split batches until #347 lands.
  - The web would need a second canvas stack beside RN-Skia web.

**C. Thin wrapper over Reanimated layout animations, plus View Transitions on the web.**

- **For:** it is the cheapest by far.
- **Against:**
  - There is no shatter, dust or angled reveal.
  - Custom functions do not run on the web, and springs do not run on the web.
  - View Transitions are DOM-only and cannot be interrupted.
- It fails the core of the request.

**Dropped:**

- Motion and Moti: web-only, or stalled.
- GSAP: proprietary licence.
- HTML-in-Canvas as the primary path: Chromium only, and the element must live inside the canvas.
- N animated Views per shard: Reanimated's guidance is about 100 views on Android.
- A canvas per animated component: on 2.14 web, each canvas is a WebGL context.

### 6.2 Naming

**Recommendation: library prefix plus a factory.**

- **Components:** `FlareButton`, `FlarePressable`, `FlareView`, `FlareFlatList`, `FlareItem`,
  `FlareToaster`, `FlareTooltip`, `FlareModal`, `FlareFxHost`.
- **Factory:** `createFlareComponent(Component)`, for anything else: FlashList, Expo Image, the
  `@flare-engine/ui` components, or app components. The component must forward a ref to a host
  view, and the factory is never called during render. Moti and Motion document the same two rules.
- **Presets:** `shatter`, `disintegrate`, `dust`, `slide`, `fade`, `emerge`, `press`.
- **Composition:** `sequence`, `parallel`, `stagger`, `delay`.

The evidence (local notes, `research-components.md` §7):

- **Prefixes are the RN animation-library norm:** `MotiView`, `EaseView`, `AnimatedLegendList`.
- **Factories are equally common:** `createAnimatedComponent`, `motion.create`, `motify(X)()`.
- **Prefixes avoid collisions.** An unprefixed `Button`, `FlatList` or `Modal` clashes with
  `react-native` imports in the same file.
- **`FButton`:** no instance was found in any library read. It is cryptic, does not autocomplete
  from "Flare", and has no precedent.
- **A `Flare.Button` namespace object** keeps every member alive (Motion documents 43 kB that cannot
  be tree-shaken). It breaks the repo's no-barrel rule and conflicts with `"use client"` (HeroUI).
  If dot notation is wanted, `import * as Fx from '@flare-engine/ui-fx'` gives it for free.

### 6.3 API sketch

These are illustrative signatures, not a contract.

```tsx
import { FlareButton, FlareItem, FlareProvider, toast } from '@flare-engine/ui-fx';
import { emerge, fade, sequence, shatter, slide } from '@flare-engine/ui-fx/core';
import { FlareFxHost } from '@flare-engine/ui-fx/fx';

<FlareProvider>
  <FlareFxHost>{app}</FlareFxHost>
</FlareProvider>

<FlareButton
  label="Delete"
  // `label` is optional sugar for an unstyled <Text>; children work the same way
  enter={emerge({ angle: 135, softness: 0.4, duration: 0.45 })}
  exit={shatter({
    fragment: { pattern: 'radial-glass', count: 40, seed: 7 },
    force: { kind: 'radial', origin: 'press', strength: 900 },
    physics: { gravity: 1800, drag: 1.2, spin: 360 },
    duration: 0.9,
  })}
  press={press({ scale: 0.96 })}
  exitOn="press"
  onExited={removeRow}
/>

<FlareItem
  itemKey={item.id}
  enter={slide({ from: 'right', distance: 48, spring: { duration: 0.4, bounce: 0.15 } })}
  exit={sequence(fade({ opacity: 0.7, duration: 0.06 }), disintegrate({ cell: 4 }))}
/>

toast('Saved', { enter: slide({ from: 'top' }), exit: dust({ angle: 90 }) });

const fx = useFlareFx(ref);
await fx.play(shatter({ fragment: { count: 12 } }));
```

- Presets are plain, serialisable data objects built by factories. The same object works in
  `enter` (played reversed for fragment presets, i.e. assemble-in) and in `exit`.
- Named presets can be registered once and referenced by string, as Tamagui does with
  `transition="bouncy"`: `registerFlarePreset('delete', shatter({...}))`, then `exit="delete"`.
- **Callbacks:** `onEntered`, `onExited`, and `onFx({ phase: 'start' | 'end', cause: 'enter' | 'exit' | 'play', finished })`.
  The shape follows Tamagui v3's `onTransition`.
- **Where the snapshot runtime comes from.** The root entry never imports Skia. A snapshot preset
  (`shatter`, `disintegrate`, `dust`, shader `emerge`) is plain data. The `FlareFxHost` from `./fx`
  registers the snapshot runtime through React context. Without a host, a snapshot preset plays its
  live fallback, with a warning in development builds.
- **External progress.** Any element or effect accepts `progress?: SharedValue<number>` instead of
  its own clock, for gesture or scroll scrubbing. For a snapshot effect, the capture is taken on
  `fx.prepare()` (or the first non-zero value) and held until the progress returns to 0 or the
  element unmounts.

### 6.4 Runtime

**Presence.**

- `FlarePresence` and `createFlareComponent` keep an exiting element mounted until its exit resolves,
  with the same contract as Motion's `usePresence → safeToRemove`.
- Lists use `useFlarePresenceList(data, keyExtractor)`, which keeps removed keys rendered until
  their exit ends, so exit is data-driven (§3.5).

**Live runtime.**

- Each element owns one `progress` shared value.
- The preset compiles to a worklet style function, evaluated in `useAnimatedStyle`.
- Springs are closed-form, so no `withSpring` is involved and the web gets springs too.
- Press feedback runs through the driver as a second shared value, combined in the same style
  function (C29). A pseudo-selector would own the `transform` property and fight enter/exit (§3.2).

**Snapshot exit, in order:**

1. **JS thread:**
   - Measure the element (`getBoundingClientRect` in `useLayoutEffect` or at the trigger; the
     element must be mounted, because 4.7 `measure` returns `null` after unmount).
   - Capture it.
   - Generate or fetch the cached fracture.
   - Fill the per-fragment initial arrays: home position, initial velocity, spin, delay, life.
2. **One transfer** of those arrays to the UI runtime.
3. **UI thread, one frame:**
   - The host mounts the effect layer with its first frame drawn.
   - The element's animated style sets opacity to 0 **on the same frame**, driven by one shared
     handoff value, so nothing flickers.
4. **Release.** The element is unmounted or removed from the data. The presence `safeToRemove`
   fires here, and a list closes the row's gap while the fragments fly, as Telegram's delete does.
   `holdSpace: true` instead keeps an empty placeholder of the element's size until the overlay
   ends.
5. The overlay plays, the layer unmounts at the end, and `onExited` fires then.

**Lifecycle rules for snapshot exits:**

- **Two moments, two signals.** `safeToRemove` (and the list's data removal) fires at handoff.
  `onExited` fires when the overlay finishes. A controlled caller (`exitOn` + `onExited`) removes
  its data in `onExited`, and with `holdSpace` the hole stays until then. `useFlarePresenceList`
  retains and releases keys itself, at handoff.
- **Interruption.**
  - Before handoff, while the capture is in flight, a cancel or re-enter cuts back to the live view
    and reports `finished: false`.
  - After handoff the exit cannot be interrupted, because the live view is gone. If the same key
    re-enters, the old overlay finishes on its own, and the new element plays its own `enter`.
  - Live presets stay fully reversible mid-flight.

**Snapshot enter (assemble-in), in order:**

1. Mount the element laid out off-window, so the capture is not blank (Android multiplies opacity
   into the bitmap).
2. Capture it.
3. Move the element into place with opacity 0.
4. Play the reversed fragment preset.
5. Reveal the element on the last frame. To follow a scrolling target, the overlay re-reads the
   anchor through Reanimated `measure` on the UI thread.

**The capture seam** is `captureView(ref): Promise<FxImage | null>`. It is the only place that knows
the platform:

- **Native:** `makeImageFromView`.
- **Web (react-native-web and React DOM):** a pluggable rasterizer. The `modern-screenshot` adapter
  (`domToCanvas`) produces a canvas, which CanvasKit uploads with `MakeImageFromCanvasImageSource`
  (§6.11). HTML-in-Canvas is a possible Chromium fast path, later.
- **v3:** RN WebGPU `drawElementImageToTexture` (#349).

If no capture is available, a snapshot preset degrades to its declared live fallback, with a warning
in development builds.

**`FlareFxHost`:**

- **Native:** one RN-Skia `<Canvas pointerEvents="none">` absolutely filling the window, as the last
  child of the root.
- **Web (react-native-web and React DOM):** one fixed `<canvas>` with `pointer-events: none`,
  portalled into `document.body` and drawn through CanvasKit (§6.11).
- The nearest host wins, so a `FlareFxHost` can be placed inside a `Modal`.
- **iOS:** `FullWindowOverlay` is used when react-native-screens is present.
- **Android:** TextureView by default; `android.surfaceType: 'SurfaceView', zOrderOnTop` is an
  option for drawing above native screens.
- **Web:** CanvasKit loads lazily on the first snapshot effect, so an app that only uses live presets
  never downloads 2.9 MB.

### 6.5 Rendering tiers by density

The preset's `density` (0..1) or explicit `fragment` block selects the tier. `maxFragments` clamps the
count by device and raises the cell size when exceeded, as Telegram's device-class caps do.

| Tier | Pieces | Technique | Per-frame work |
|---|---|---|---|
| Shards ("glass") | 8-300 convex polygons (grid, triangles, radial glass; Voronoi later) | **Shard-atlas bake.** At trigger, draw each polygon, clipped from the snapshot, into one raster atlas with padding. Animate rigid RSXforms through `<Atlas>`. | n RSXforms from closed form; zero allocation |
| Grains ("gravel to sand") | ≈500-5k rect cells, 2-8 px | `<Atlas>` sprites cut straight from the snapshot, with per-sprite `colors` for alpha (explicit blend mode) | n RSXforms plus n colours |
| Dust ("sand to smoke") | effectively unlimited | `<Shader>` with an `<ImageShader>` child on a rect enlarged beyond the element: noise threshold, directional sweep, displacement, edge glow. A few hundred grains can be emitted at the sweep front. | One fragment pass, plus optional grains |

- **Why bake rather than `<Vertices>` for shards.** 2.14 rebuilds `SkVertices` from `SkPoint[]` on
  every draw (§3.3), whereas the bake costs one raster pass per trigger and then runs the existing
  zero-allocation Atlas path.
- **Where `<Vertices>` is still needed:** fake 3D "tumble" (non-uniform squash) needs it, so tumble is
  a later preset option.
- **Bake surface.** The bake uses a raster surface, so the result is a CPU image that is safe to
  sample from any context. A GPU offscreen surface would have to be built on the UI thread
  (`game-view.tsx:43-60`, the XR-1c lesson). G3 confirms the raster route on both backends.

### 6.6 Data flow and threads

| Step | Thread | Allocation |
|---|---|---|
| Seeded draws, fracture, initial arrays | JS, once per trigger | Pooled `Float32Array`s sized by tier capacity |
| Hand-off to the UI runtime | one transfer per trigger | One copy (G8 measures it) |
| Closed-form evaluation into Atlas buffers | UI, per frame | None |
| Effect-layer mount and unmount | JS (React), once per trigger | One small React render, never per frame |
| Web | the main thread runs both | Same code. The RN-Skia web `drawAtlas` wrapper allocates per call (§3.3); accepted, measured in G4. |

Worklets are self-contained: no React Native imports, and no helper calls that are not themselves
worklets. They therefore run in Legacy Eval and Bundle Mode without consumer `importForwarding`.

### 6.7 Components

**`FlareButton` / `FlarePressable`**

- They wrap RN `Pressable` and render children. `label` is optional sugar for an unstyled `Text`.
  Styling stays with the app or with `@flare-engine/ui`.
- `exitOn="press"` plays the exit and then calls `onExited`.
- The press origin (`locationX/Y`) feeds `force.origin: 'press'`.
- `TouchableWithoutFeedback` is never used, because it overwrites `nativeID`, which Reanimated needs.

**Lists**

- `FlareItem` is the primitive. Enter fires on first key appearance, and state resets on a key change,
  which covers FlashList recycling.
- `FlareFlatList` is sugar over `Animated.FlatList`, with `itemLayoutAnimation` closing gaps, plus
  `stagger`.
- FlashList v2 and Legend List adapters are optional subpaths in a later issue.

**`FlareToaster` + `toast()`**

- Sonner's vocabulary: `position`, `visibleToasts`, `gap`, `offset`, `duration`; queue modes from
  react-native-notifier; safe-area offsets.
- Swipe to dismiss is optional.
- A second toaster can be mounted inside a Modal.

**`FlareTooltip`**

- Anchors with `getBoundingClientRect()` in `useLayoutEffect` (RN 0.82+, and RNW host elements) and
  forces `collapsable={false}`.
- A small in-house placement solver handles side, align, flip, shift and the arrow (call C12).
- Triggers are press, long-press, hover (web and desktop) and focus.

**`FlareModal`**

- RN `Modal` with `transparent` and `animationType="none"`, so the presets own the motion.
- A backdrop preset and its own nested `FlareFxHost`.

### 6.8 Accessibility

- **Per-component `reduceMotion`** with values `'system'` (default), `'always'` and `'never'`, plus a
  **calm fallback preset** per effect. The default fallback is `fade({ duration: 0.15 })`, not
  Reanimated's "omit the exit".
- **A live OS bridge:**
  - native: `AccessibilityInfo` `reduceMotionChanged`
  - web: a `matchMedia('(prefers-reduced-motion: reduce)')` listener
  - It optionally pushes into a host app's `A11yManager`.
- ui-fx never mounts `ReducedMotionConfig`.
- **Exiting elements leave the accessibility tree when the exit starts:**
  `importantForAccessibility="no-hide-descendants"` and `aria-hidden` on the web. The overlay canvas
  is not accessible.
- Focus moves off a focused element that shatters.

### 6.11 The web driver (react-native-web and plain React DOM)

One driver serves both web hosts. They differ only in how the host element is reached:

- **react-native-web:** a ref to an RNW host component is the DOM node.
- **React DOM:** the element ref.

**Live presets: Web Animations API.**

- `core` compiles the preset to the same closed-form pose the native worklet evaluates.
- The web driver samples that pose into WAAPI keyframes (about 60 per second of animation, linear
  between samples). It plays them with `element.animate(..., { composite: 'add' })`, layering on top
  of the element's own transform.
- Springs, Penner curves and path slides are therefore exact on the web, and transform and opacity
  run on the browser's compositor thread.
- Interrupting reads `currentTime` and reverses or cancels. External `progress` drives `currentTime`.
- Reanimated is not used on the web, so react-native-web apps need no Reanimated web setup for
  ui-fx.
- Facts: WAAPI `composite` and `linear()` easing (§3.8). `@property` angles are needed only for the
  live emerge mask.

**Snapshot effects: CanvasKit direct, not RN-Skia web.**

- One fixed, full-viewport `<canvas>` is portalled into `document.body`.
- `@flare-engine/render-web`'s `createWebSurface` gives the CanvasKit canvas.
- `drawAtlas` takes reusable `Float32Array` / `Malloc` buffers. The RN-Skia web wrapper allocates on
  every call and costs one WebGL context per `<Canvas>` (§3.3).
- **CanvasKit source:**
  - an instance passed to the host (`canvasKit` prop)
  - else `globalThis.CanvasKit` when RN-Skia's `LoadSkiaWeb` already loaded it (one copy per page)
  - else `loadCanvasKit(wasmUrl)`, which caches itself
- **Capture:** the pluggable rasterizer (D5). `modern-screenshot`'s `domToCanvas` result is uploaded
  with `MakeImageFromCanvasImageSource`.
- **Shaders:** the SkSL in `core` compiles through CanvasKit `RuntimeEffect.Make`, the same source
  the native host compiles.
- **Context loss:** the host listens for `webglcontextlost` and `webglcontextrestored`, as
  `render-web`'s postfx surface does. A lost context ends any running effect with
  `finished: false`.
- **Draw loop:** `requestAnimationFrame` on the main thread while an effect runs, and idle
  otherwise.

### 6.12 Coverage: which components can be animated

| What | Live presets (slide, path, fade, live emerge, press) | Snapshot presets (shatter, grains, dust, shader emerge) |
|---|---|---|
| A component whose ref reaches a host view (RN) or DOM element | Yes, through `createFlareComponent` | Yes, where capture works |
| A component that takes no ref, or several roots (e.g. `@flare-engine/ui` today) | Yes, inside `FlareView` / `FlareDiv` | Yes, captured through the wrapper |
| Virtualised list rows (FlatList, FlashList, Legend, any keyed DOM list) | Yes, through `FlareItem` / `FlareList`, keyed on identity | Yes, while the row is rendered |
| Native surfaces: video, maps, camera, WebView, SurfaceView-backed canvases, DRM content | Yes (transform and opacity apply to the view) | **Often blank.** The Android capture special-cases TextureView and SurfaceView (§3.3); falls back to live |
| Web: cross-origin images without CORS, `<iframe>`, `<video>` frames, WebGL canvases without `preserveDrawingBuffer`, `backdrop-filter` backgrounds | Yes | **Partial or blank** (§3.8); falls back to live |

So **every RN and React component can take every live preset**. Snapshot presets work on
everything the platform can rasterise, and fall back cleanly where it cannot. The README
publishes this table.

### 6.13 Threads: is the JS thread optimal?

No. The thread each piece runs on:

| Work | Native | Web |
|---|---|---|
| Live preset frames | **UI thread**, a Reanimated worklet over the shared `progress` | **Compositor**, WAAPI (transform, opacity) |
| Snapshot effect frames | **UI thread**, worklets filling `<Atlas>` buffers | **Main thread**, `requestAnimationFrame` drawing CanvasKit |
| Per-trigger setup (measure, capture, fracture, initial arrays) | JS thread, once | Main thread, once |
| React reconciliation | JS thread, once per trigger | Main thread, once per trigger |

The JS thread is where React re-renders the app at exactly the moment an effect fires: deleting a
row, dismissing a toast. Per-frame work there would stutter the very frames the effect is meant to
make smooth. That is why per-frame work runs on the UI thread or the compositor, and the JS thread
does one-off setup only. This departs from ADR-0001's JS-thread game loop (C16).

On the web there is only one main thread, so the snapshot draw loop shares it with React. A
post-0.5.0 option moves CanvasKit into a Web Worker on an `OffscreenCanvas`, with the capture sent
as a transferable `ImageBitmap` (C28).

## 7. Preset parameter model

### 7.1 Conventions (calls C1-C4)

- **Durations are in seconds**, like the engine's `tween`, `spring` and scene transitions.
- **Angles are in degrees, 0° = up, clockwise**, the After Effects and CSS convention. An angle
  always means the **direction of travel**.
- **Origins** are normalised element coordinates (0..1), or `'press'` (the touch point), or `'center'`.
- **Springs** take `{ duration, bounce }` with bounce in -1..1 and a default of 0. The escape hatch is
  `{ stiffness, damping, mass }`. Both resolve to (ω0, ζ) and the closed-form solution.
- **Easing** accepts a Penner name, `cubicBezier(x1, y1, x2, y2)`, or a sampled table, which exports to
  CSS `linear()`.
- **Every preset has `completion` 0..1**, so it is scrubbable and drivable from a gesture.

### 7.2 Fragment presets: `shatter`, `disintegrate`, `dust`

```
fragment  pattern  'grid' | 'jittered-grid' | 'triangles' | 'radial-glass' | 'voronoi'(later) | 'cells'
          count 2..300 (shards) | cell 1..8 px (grains) | density 0..1 (picks tier and count)
          distribution 'uniform' | 'normal' | 'inverse-normal' | 'exponential'   (C4D)
          focus {x,y}  deviation 0.01..0.7  jitter 0..1  anisotropy {x,y}  gap px  rotation deg  seed
          subdivide {depth, chance, select: 'near-impact' | 'small' | 'random'}  (Blender recursion)
force     up to two: kind 'radial' | 'directional' | 'vortex' | 'implode'
          origin  radius  strength (negative = pull-through)  falloff  angle  spread
release   order 'radial' | 'sweep' | 'random'   duration (front crossing time)  softness  timingRandomness
physics   gravity  gravityAngle  drag (AE viscosity)  angularDrag  spin  randomness  massVariance (0.3)
          depth (fake z: scale and alpha)  collide 'none' | 'floor' | 'bounds'
life      opacityOverLife  scaleOverLife  tintOverLife  lifetime  lifetimeVariance
reverse   'rewind' | 'home' | 'spring-home'   (assemble-in mode)
dust only noiseScale  noiseAmount  edgeWidth  edgeColor  sweepAngle  grainsAtFront
common    duration  delay  completion  maxFragments  reduceMotion  fallback
```

### 7.3 `slide`

```
from      'left' | 'right' | 'top' | 'bottom' | {angle, distance} | {x, y}
path      cubic segments | points + curviness | SVG path data
alignOrigin {x,y}   autoRotate boolean | offset deg   rotationLimit deg
start/end 0..1 (may go below 0 or above 1)   stops [{at, easing}]   (arc-length fractions)
timing    duration + easing | spring {duration, bounce}
```

### 7.4 `fade` and `emerge`

```
fade      opacity (the "away" state, default 0: enter animates opacity→1, exit 1→opacity)
          duration  easing | spring
emerge    angle  softness 0..1  falloff  distance px
          shadow {color, opacity, lag 0..1, blur px, length px}   sheen {width, intensity, color, delay}
          variant 'live' | 'shader'   ('live' = gradient overlay + brightness + translate; no snapshot)
```

### 7.4b `flip`, `iris` and `swap` (added 2026-11-16, owner request)

**`flip`** is live (3D):

```
flip      axis 'x' | 'y'   angle deg (default 90, the away rotation)   perspective px (default 800)
          origin OriginSpec (the transform origin, default 'center')   fadeAtEdge boolean (default true)
          duration (default 0.45)  easing | spring
```

- Native: RN `perspective`, `rotateX` and `rotateY` transforms.
- Web: `perspective()`, `rotateX()` and `rotateY()` in the WAAPI transform.
- `LivePose` gains three channels for this: `rotateXDeg`, `rotateYDeg`, `perspective`. Custom live
  presets can use them too (§7.6).

**`iris`** is a snapshot preset, a shader mask. It is the circular reveal from §3.9's Telegram and
Candillon prior art.

```
iris      origin OriginSpec (default 'press')   shape 'circle' | 'rounded-rect' | 'diamond'
          feather px (default 2)   ring {width px, color} | null   duration (default 0.5)  easing
```

- **Exit:** the element disappears through a closing shape toward `origin`.
- **Enter:** it appears through an opening shape.

**`swap(update, preset)`** on `useFlareFx` animates a **content change** rather than an enter or exit:

- **Live preset** (for example `flip`): play the exit, apply `update()` at its end, then play the
  enter.
- **Snapshot preset** (for example `iris`):
  1. Capture the old state.
  2. Draw it full-size in the overlay.
  3. Only after that first frame, apply `update()`.
  4. Once React commits, grow a hole in the old image so the new live content shows through.
  - This is the Telegram theme switch. Updating only after the old image is on screen prevents a
    flash of the new state.

### 7.5 Composition

`sequence(...)`, `parallel(...)`, `stagger(step, ...)` and `delay(s)` produce a timeline. Each step is
a preset or a nested timeline. A timeline can mix live and snapshot steps. A snapshot step ends the
element's live life, because the view is hidden from then on.

### 7.6 Extension points (C33)

Apps can add new animation kinds without an engine change.

- **`defineLivePreset(name, { duration, pack, pose })`** returns a preset factory.
  - `pose(t, direction, w, h, params: Float32Array, out: LivePose)` is a worklet that writes any
    `LivePose` channel.
  - Native evaluates it on the UI thread. The web samples it into WAAPI keyframes like the built-in
    presets.
  - The preset's kind is `'custom-live'`.
- **`shaderEffect({ sksl, uniforms, duration, spread, easing })`** is a snapshot preset.
  - The SkSL contract is `uniform shader image; uniform float u_progress; uniform float2 u_size;`.
    Further uniforms are packed by name, as the engine's custom sprite shaders already do
    (`packages/react/src/skia-bridge.ts`).
  - It runs on both backends through the same `<Shader>`/`RuntimeEffect` path as `dust`.
  - The preset's kind is `'custom-shader'`.

These two kinds exist from the first release, so later app-defined animations never widen the
public `FlarePreset` union. New `LivePose` channels beyond the eleven listed in the plan's Task 8
(for example blur or clip) still need an engine change.

- **C32.** Default caps until G2 and G3 measure: shards ≤ 300, cells ≤ 3,000, and a capture or

- **C33.** The extension points from §7.6 (`defineLivePreset` and `shaderEffect`) ship before
  0.5.0. Approved by the owner on 2026-11-16.
- **C34.** Two more presets, at the owner's request on 2026-11-16 (§7.4b):
  - `flip` (3D, live)
  - `iris`, a circular reveal from the touch point, chosen as the strongest prior art in §3.9
  - `swap(update, preset)` for animating content changes
  - `LivePose` grows from 8 to 11 channels for 3D.
- **C35 (from G4).** With `exitOn: 'press'`, the snapshot capture starts at press-in (`prepare()`),
  not at release. The ~110 ms gradient captures in Firefox and WebKit then usually finish before the
  finger lifts. A release before the capture finishes keeps the live view until the capture lands.
- **C36 (from G4).** Captures are padded by `capturePadding` (default 24 px; `0` turns it off) on
  every side, so a `box-shadow` or elevation shadow is part of the image.
  - The overlay draws the padded image offset by the padding.
  - On the web, capture with `width`/`height` + 2p and `style: { margin: p }`.
  - On native, check with G1 whether `makeImageFromView` includes elevation shadows. If it doesn't,
    the native wrapper captures an outer host with padding.
- **C37 (from G4).** ui-fx's web docs and the web host name the full CanvasKit binary
  (`canvaskit-wasm/bin/full/canvaskit.wasm`). The host turns a non-`Error` rejection from
  `loadCanvasKit` into a fallback with a message naming that file. #422 fixes the root cause in
  render-web.

- **G10: pass.**
