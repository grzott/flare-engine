# Changelog

Flare versions **in lockstep**: every `@flare-engine/*` package shares one version and moves
together on every release, so "Flare 0.3.1" names the whole set rather than any single package.
That is enforced by the `fixed` group in [`.changeset/config.json`](.changeset/config.json).

This file is the index. **Per-package detail lives in each package's own `CHANGELOG.md`**
(`packages/<name>/CHANGELOG.md`), generated by Changesets — that is the source of truth for what
changed in a given package, and it is not duplicated here.

> **Availability.** `0.1.0` through `0.4.4` were published **restricted**. On 2026-10-26 the
> `@flare-engine` scope went public, and npm visibility is retroactive, so every version below
> installs without authentication. `0.4.5` is the first release published as public, from CI with
> npm provenance. See [`docs/plans/road-to-oss-2026-09.md`](docs/plans/road-to-oss-2026-09.md).

## 0.4.19

Fixes, additions and docs in 12 packages. The other 30 change only their version. There are two
behaviour changes, in `render` and `scene`. This release also announces the twelve changes that
0.5.0 makes ([ADR-0012](docs/design/adr-0012-0-5-0-breaking-set.md)), each in the JSDoc of what it
changes. Nothing announced here changes in this release.

- **`render`**: the shader sprite effects `custom`, `water`, `fog` and `fire` now show (#581).
  - **What was wrong:** Skia ignores a paint's shader when the draw is a colour image, so these
    effects drew the plain sprite. Each such sprite is now a `drawRect` over its destination, with
    the shader on the paint.
  - **Behaviour change:** the shader's output replaces the sprite. The atlas frame is not drawn and
    is not passed to the shader.
  - **Coordinates:** they are sprite-local, `(0, 0)` at the destination's top-left and `(dstW, dstH)`
    at its bottom-right. Rotation and flips turn and mirror them with the sprite. This is documented
    on `CustomShaderEffect`.
  - **Alpha and blending:** alpha and `blend: 'additive'` apply to the shader's output. A per-sprite
    colour contributes only its alpha. `stretch` and `setImageSampling` have no effect on these
    draws.
  - **No shader available:** without `Skia.RuntimeEffect`, or when a built-in shader fails to
    compile, `water`, `fog` and `fire` still draw the plain sprite.
- **`scene`**: `SceneManager.go()` called from a scene's `onEnter` now takes effect under an
  animated transition (#582).
  - **What was wrong:** the manager started its fade-in over the fade-out that the call had just
    begun. The target was never entered, and `push()` and `pop()` were ignored from then on.
  - **Now:** the scene that redirected stays current until its fade-out ends. An instant `go()` or a
    `destroy()` from that `onEnter` no longer leaves a fade-in running.
- **`react`**: on the web, `GameView` draws again after its on-screen canvas loses its WebGL
  context (#583).
  - **What was wrong:** nothing listened for the loss, so the field stayed black while the loop and
    the overlay children kept running.
  - **Now:** it listens for `webglcontextlost` and `webglcontextrestored` on the on-screen canvas.
    At the restore, or on the first frame after a loss with no restore by then, it rebuilds the scene
    capture and remounts `<Canvas>` onto a new canvas and context. Native is unchanged.
  - **Limits:** a loss of only the capture context is still not detected (#605). The recovery is
    tested with mocked events, not yet against a real context loss in a browser (#604).
- **`physics`**:
  - **A faster crowded broadphase (#579).** `CollisionWorld` has its own grid, which groups each
    cell's bodies by layer and mask, so `step()` tests layer and mask once per group. `setPosition`
    skips the relink while a body stays in the same cells, and so does `SpatialIndex.update`, which
    also removes from a bucket in O(1).
    - On the new `physics.curtain` rows (2000 enemy bodies that never pair with each other, 100
      shots and a ship, measured on a shared CI runner), a `setPosition` pass went from 322-343 µs
      to 138-142 µs, and `step()` from 1.27 ms to 117-126 µs.
    - Which pairs a step reports, and which signal each gets, is unchanged. Two orders that were
      never specified can differ: the order in which one `step()` emits pairs that share their lower
      entity id, and which of two colliders `raycast` returns at exactly the same distance.
  - **Pixel-mask collision (#580):** `MaskShape` and `MaskPose`, built with `createMaskShape` and
    `createMaskPose`, tested with `maskOverlapsBox`, `maskOverlapsSweptBox`, `maskOverlapsCircle`
    and `maskOverlapsMask`, plus `rayVsMask`, `maskStripStop`, `isMaskSolidAt` and `maskBounds` /
    `maskBoundsInto`. A mask is not part of the `Shape` union: keep a box collider for the
    broadphase and refine its pairs with these. None of the per-frame functions allocates.
  - **Docs (#510):** the broadphase cell is a fixed 64 world units, so scale tile-sized worlds up. A
    ray that starts inside a collider hits it at its exit distance.
- **`debug`**: new `createStatsTracker()`, returning a `StatsTrackerHandle` with the same members as
  the `StatsTracker` class (#177). The class is `@deprecated`.
- **`ecs`**: the npm description and the README now describe the storage as `World` implements it:
  numeric entities, Map-backed components and bitmask-matched queries (#514). Docs only.
- **Announced for 0.5.0** (ADR-0012 rows 5-12; rows 1-4 were announced in 0.4.10 and 0.4.14):
  - **`math`:** `springIn`, `springOut` and `springInOut` are removed. Use `easeInBack`,
    `easeOutBack` and `easeInOutBack`.
  - **`debug`:** the `StatsTracker` class is removed. Use `createStatsTracker()`, and annotate with
    `StatsTrackerHandle`.
  - **`ui`:** `refocusOnUnregister` defaults to `false`.
  - **`shapes`:** `glow: 'friendly'` and `glow: 'hazard'` are removed.
    - `'friendly'` becomes `{ color: friendlyGlowArgb(), width: 3 }`, the same pixels.
    - `'hazard'` becomes `{ color: hazardGlowArgb(), width: 1 }`, one ring in place of two, its
      inner edge 2.5 px outside the shape instead of 0.75 px.
  - **`particles`:** `drawParticles`' `color` option defaults to `true`.
  - **`audio`:** `AudioContextLike.createBufferSource()` may return a `PromiseLike`.
  - **`react` and `engine`:** the `react-native-reanimated` peer floor rises to `>=4.1.0`.
  - **`render`:** `BitmapFont.kernings` is keyed `first * 0x200000 + second`, and text is read by
    code point, so glyph ids above 0xFFFF measure, draw and kern.
  - `SceneManager.pop()` keeps its default (#179, declined).

## 0.4.18

A fix in 1 package and docs in 2. The other 39 change only their version. One behaviour change, in
`pathfinding`.

- **`pathfinding`** — `findPathJPS` no longer cuts corners, so it now follows `findPath`'s rule: a
  diagonal step is taken only when both cardinal neighbours it passes are walkable (#507).
  - **What was wrong.** On a uniform-cost grid, JPS stepped diagonally past a wall's tip where
    `findPath` went round. It also switched to `findPath`'s rule whenever any tile cost more than 1,
    even off the route. A game that checked reachability with one function and moved units with the
    other could send units through a gap the check had reported as sealed.
  - **Now:** on a uniform grid both return a path of the same cost, and both return `null` when only
    a corner cut would connect start and goal.
  - **Behaviour change:** a `findPathJPS` path on a uniform grid may be longer than before, by
    `2 - √2` for each corner it used to cut, and may go round where it used to squeeze through.
  - **Speed:** in the published benchmarks, a JPS search on the 128×128 open map now takes 148 µs
    (was 94 µs; A* takes 8 µs), and on the 128×128 maze 40 µs (was 55 µs; A* takes 46 µs). On the
    256×256 maps measured in #574, JPS took 1.3-2× longer than before, and still searched 2.3×
    faster than A* on a rooms-and-corridors map and 1.3-1.4× faster with 10-20% scattered walls.
- **`react`** — `GameConfig.opaque` no longer recommends `true` on Android. Docs only; the default
  stays `false`. On a 90 Hz Pixel 7, `opaque: true` ran the game loop at 45 Hz (30 Hz at 60 Hz),
  with frames reaching the screen about 40 ms after they were queued. The default loops at the
  display rate. Its one cost, a harmless react-native-skia log pair on every render, can be
  filtered out of logcat as the JSDoc shows. Keep `opaque: true` only for overlays that a
  TextureView clips (#545).
- **`engine`** — the README and the package description no longer call `./headless` safe for
  web-only and Node projects. Docs only. `./headless` imports no React Native, but installing
  `@flare-engine/engine` installs React Native, Skia, Reanimated and Worklets as required peers. A
  new README section, "Web and Node without React Native", says to install the leaf packages
  instead, and gives what to build in place of `createGame` and how to run a `GameLoop` in Node
  (#505).

## 0.4.17

Fixes and type additions in 6 packages. The other 36 change only their version. Two behaviour
changes, in `render` and `render-web`.

- **`render`** — `Camera2D.shake()` moves about the same whatever rate `update()` is called at.
  Every `update()` used to draw a new, unrelated jitter value, so a faster display shook harder: one
  `shake(10, 1)` travelled about 201 units along X at 60 Hz and 549 at 165 Hz. The jitter is now a
  function of the shake's elapsed time, 30 values per second eased from one to the next, and the
  same shake travels about 90 units at 60 Hz and 97 at 165 Hz. **Behaviour change:** the shake looks
  different. It is smoother and covers about half the ground per second that the old shake did at
  60 Hz; the maximum offset is the same. Code that compared `effectiveX` / `effectiveY` during a
  shake against recorded values needs new values. Intensity, duration, the linear decay,
  `setMotionScale` and `shakePerlin` are unchanged.
- **`render-web`** — `loadCanvasKit` rejects a later call that names a different `wasmUrl`, with an
  `Error` naming both URLs, instead of silently returning the kit loaded from the first URL. The
  first load and its promise are unaffected. A later call with the same `wasmUrl` behaves as before;
  URLs are compared as exact strings, so pass the same string each time. A failed load is still not
  cached. **Behaviour change** only for code that passed a second, different URL. The README gains
  a "Sizing" section: the caller owns canvas size and `devicePixelRatio`, and calls
  `PostFxSurface.resize()` (or disposes a `WebSurface` and creates a new one).
- **`react`** — `GameView` picks up a pixel-ratio change after it mounts. It re-reads
  `PixelRatio.get()` on every render and on a `Dimensions` `change` event. From the next frame, the
  frame, the scene capture and, on web, the postfx passes use the new physical size. A scale change
  that causes neither a render nor a `change` event is still not seen.
- **`assets`** — a CanvasKit `Image` is assignable to `SkImageLike`, so it can be passed to
  `createTexture` and returned from a `decodeImage` callback with no cast. `SkImageLike.readPixels`
  now declares optional `srcX`, `srcY` and `imageInfo` parameters, typed by the new exported
  `SkImageInfoLike`. Type-only. The arguments are not portable between backends, so read pixels back
  through the backend's own image type.
- **`shapes`** — the published types no longer import `@shopify/react-native-skia`, so they resolve
  in a project without that optional peer. `drawShape`, `applyGlow`, `applyFriendlyGlow` and
  `applyHazardGlow` take the package's structural `ShapeAtlasCanvas`, `ShapeAtlasPaint` and the new
  `ShapeDrawSkia`. react-native-skia's types and the handle from `createWebShapeSkia` pass with no
  cast. Type-only. On the web the per-frame path is `bakeShapeAtlas` followed by `drawBakedShape`.
- **`ui`** — `Button`, `Panel` and `Label` accept an optional `ref`, React 19's ref-as-a-prop, and
  pass it to their root element.

## 0.4.16

One fix, in `shapes`. The other 41 packages change only their version.

- **`shapes`** — `drawShape` and `bakeShapeAtlas` work with react-native-skia 2.14, the version the
  scaffolder's Expo SDK 58 templates pin. 2.14 removed the `SkPath` mutators that 2.6 deprecated, so
  seven kinds threw a `TypeError`: `triangle`, `ngon`, `star`, `polyline`, `arc`, `trapezoid`, and
  an `annulus` with `startAngle` and `endAngle`. `bakeShapeAtlas` threw with them, because it draws
  through `drawShape`. Those kinds now build on `Skia.PathBuilder` whenever the handle has one. A
  handle without it (react-native-skia before 2.6, and `createWebShapeSkia` from `render-web`) is
  driven exactly as before. `ShapeAtlasSkia` declares `Path.Make()` as returning `unknown` and gains
  an optional `PathBuilder`, so react-native-skia 2.14's `Skia` is assignable to it with no cast.
  **Type change:** code that reads `Path.Make()` from a value typed `ShapeAtlasSkia` and calls the
  mutators on the result no longer typechecks; build the path on your own `Skia` type instead.
  Covered by unit tests against stub handles for each version range and a type-level check; not run
  on a device.

## 0.4.15

One performance fix, in `render`. The other 41 packages change only their version.

- **`render`** — `SpriteBatch.draw` and `SpriteBatch.drawRaw` no longer do per-sprite colour
  bookkeeping while no coloured sprite is queued. Since 0.4.13 every sprite paid for it, coloured or
  not, which is the slowdown the 0.4.13 entry lists as **Known** (#434). The bookkeeping now starts
  at the first coloured sprite of a frame. Runs, colours and the flush callback's arguments are
  unchanged. In the node benchmark (Bun) the uncoloured `render.flush` rows are back at their 0.4.12
  figures: `render.flush 1000 sprites / 1 atlas` 26.1 µs, against 30.0 µs at 0.4.14 and 26.0 µs at
  0.4.12.

## 0.4.14

Fixes in 3 packages, and the deprecations that 0.5.0's removals need first. The other 39 change only
their version. One behaviour change, in `ecs`, and only where two component definitions share an
`id`.

- **`ecs`** — `World` keys component storage by the `ComponentDef` object instead of its `id`. A
  second copy of the package in one process (the CJS and ESM builds loaded together, or a duplicated
  install) numbers its definitions from 0 again, so its components used to share storage and query
  matches with the first copy's, with no error. They no longer do. Query masks for definitions from
  one copy are unchanged. **Behaviour change**, only where two definitions share an `id` (two copies
  of the package, a hand-built `ComponentDef`, or one defined after the internal
  `_resetComponentIds`): they are now separate components, and a definition whose `bit` another
  definition already holds in that `World` gets a free bit. A `World` holds at most 32 component
  types and throws on the 33rd; `has`, `get` and `remove` never take a slot. `World.destroy` deletes
  only from the stores of the components the entity has.
  **Deprecated, removed in 0.5.0:** `ComponentDef.id` and `ComponentDef.bit` (key by the definition
  object instead), the internal `_resetComponentIds`, and `Query.requiredMask`, `Query.excludedMask`,
  `Query.matches` and calling `new Query(...)` directly (build queries with `World.query` or
  `World.queryBuilder`, test membership with `Query.has`). None of them changes behaviour in this
  release.
- **`testing`** — `serializeScene` cached its queries by `ComponentDef.id`, so when two definitions
  shared an `id`, entities holding only the second were left out of the snapshot. It now caches by
  the definition object.
- **`render-web`** — `loadCanvasKit` no longer rejects with a bare non-`Error` value. Such a
  rejection (the full CanvasKit glue rejects with `Infinity` when served the non-full binary) becomes
  an `Error` that names the likely cause and the file to serve,
  `canvaskit-wasm/bin/full/canvaskit.wasm`, with the original value as its `cause`. The README and
  the API spec now say that `wasmUrl` must serve the full binary.

## 0.4.13

Additions and performance work in 7 packages. The other 35 change only their version. One behaviour
change, in `postfx`.

- **`render`** — `SpriteBatch.draw` and `SpriteBatch.drawRaw` take an optional trailing `color`, a
  packed `0xAARRGGBB` multiplier for that sprite. Consecutive coloured sprites that share image,
  effect, stretch, blend and flip form one run whatever their colours and alphas. The flush callback
  receives a coloured run's colours as a third argument, `colors: Uint32Array`, and
  `FrameRenderer.drawAtlas(image, commands, colors?)` accepts it, so `batch.flush(renderer.drawAtlas)`
  needs no change. A coloured run draws with Skia's Modulate blend; on the stretch, flip and
  zone-background paths only the colour's alpha applies. Sprites drawn without a `color` batch and
  draw exactly as before. A custom flush callback or `DrawSurfaceLike` that opts in must read each
  sprite's opacity from `colors`. `DrawSurfaceLike.drawAtlas`'s `blendMode` and `colors` parameters,
  typed `undefined` before, are now `number` and `Float32Array[]`. `SpriteBatch.flush` flushes
  coloured and uncoloured queues with separate loops, so coloured sprites no longer slow down under
  JavaScriptCore in a process that has already flushed many kinds of uncoloured run.
  **Known:** the node benchmark (Bun, no rasterization) measures the uncoloured `render.flush` rows
  7-13% slower than at 0.4.12. The browser and Android lanes show no slowdown. Tracked in #434.
- **`particles`** — `drawParticles` takes a new option, `color` (default `false`). With
  `{ color: true }` each particle's interpolated colour is passed to `drawRaw` as that trailing
  `color`, so an emitter's `startColor` / `endColor` tint the particles and one call forms a single
  run per image instead of one run per distinct alpha. Without the option it makes exactly the call
  it made before. `ParticleBatchLike.drawRaw` declares the optional trailing parameters `blend?`,
  `flipX?`, `flipY?` and `color?`. The default is planned to flip to `true` in 0.5.0, behind an ADR.
- **`shapes`** — `bakeShapeAtlas(Skia, specs, scale, options?)` draws each distinct `ShapeSpec` once
  into one image and returns a `ShapeAtlas` that a `SpriteBatch` draws, so N shape-built entities are
  one run instead of several Skia draws each. `drawBakedShape(batch, atlas, index, x, y, rot?,
  scale?, color?, alpha?)` queues one instance and allocates nothing. `shapeAtlasNeedsRebake` and
  `rebakeShapeAtlas` re-bake once the scale leaves 0.75x-1.5x of the baked one; cell indices, each
  spec's origin and its drawn size carry over. No cell is rasterized above `SHAPE_ATLAS_MAX_CELL`
  (2048 px): a larger spec bakes at a lower scale of its own and draws at the same size. A spec
  whose parameters animate should stay on `drawShape`, and baked colours can be multiplied but not
  recoloured per part. The package now depends on `assets`.
- **`assets`** — `packAtlasRows(sizes, maxWidth, padding)` exports the row layout
  `createProceduralAtlas` already used, with the types `AtlasRowLayout` and `AtlasRowPosition`.
- **`render-web`** — `createWebShapeSkia(kit)` returns a CanvasKit-backed `WebShapeSkia` for
  `bakeShapeAtlas` and `drawShape`. It bakes on CanvasKit's offscreen CPU surface, so it needs no
  WebGL context. `createWebSkiaModule`'s `drawAtlas` forwards a coloured run's colours with
  `BlendMode.Modulate`; an uncoloured run still passes `null` for both.
- **`postfx`** — `runtime.buildPass` (and `PostFxController.buildPass`) no longer allocates on a frame
  where the chain's enabled set is unchanged, which closes the allocation noted under 0.4.12 (#303).
  Each runtime returns the same array and rewrites its pass objects and `uniforms` buffers in place.
  **Behaviour change:** a `buildPass` result is overwritten by the next call on the same runtime,
  including a call with a different chain, so code that keeps a result to compare later must copy
  it first. `runtime.packUniforms` still returns a new array per call.
- **`create`** — the `blank`, `topdown` and `shmup` templates ship an Expo config plugin,
  `plugins/with-windows-cmake.js`, that points Android builds on Windows at the newest SDK CMake 3.x
  from 3.31.6 on. That version's ninja handles Windows long paths; the SDK default 3.22.1 does not,
  and Skia's build rejects CMake 4. The plugin keeps a `cmake.dir` you set yourself, prints the
  install command when no such CMake is installed, warns when Windows long paths are disabled, and
  does nothing on macOS and Linux.

## 0.4.12

Fixes, additions and allocation work in 22 packages. The other 20 change only their version.

- **`events`** — a `Signal.once` or `EventEmitter.once` handler now runs at most once when the same
  signal or event is emitted again from inside the emit that fires it. Before, it could run twice,
  and a `once` handler that re-emitted its own signal recursed until it threw `RangeError`.
- **`physics`** — re-adding a `CollisionWorld` entity with a flipped `isTrigger` while one of its
  pairs is touching now ends each pair whose kind changes during the `add` call, with the exit
  signal of its old kind. If the shapes still overlap, the next `step()` starts the pair again in
  the new kind. Before, such a pair could begin with `onTriggerEnter` and end with
  `onCollisionEnd`. An axis-parallel ray whose origin lies exactly on the line of a box edge made
  `raycast()`, `rayVsShapeInto` and `CollisionWorld.raycast` return a `NaN` hit whichever way it
  pointed; it now returns a finite hit when it reaches the box and no hit when it points away, and
  a zero-length direction misses. `SpatialIndex.insert` of an item already in the index now replaces
  its bounds instead of leaving a stale entry; `CollisionWorld` users were not affected. New
  `setSolidAt(grid, col, row, solid)` and `isSolidAt(grid, col, row)` read and write one
  `SolidGrid` cell. The standalone `raycast()` now allocates only the hit it returns.
- **`math`** — `rayVsRect` gets the same edge fix: an axis-parallel ray from an edge returns a
  finite `t` or `null` instead of `NaN`, and a zero direction returns `null`. `Vec2.slerp` of
  antiparallel unit vectors no longer collapses to zero; it turns toward `Vec2.perp(a)`. New
  `argbToFloat4Into(out, argb)` unpacks a packed `0xAARRGGBB` colour into a `Float32Array`. It
  replaces five private copies, so `shapes`, `assets` and `render-web` now depend on `math`.
  `lineVsRect` no longer allocates. `springIn`, `springOut` and `springInOut` are documented as the
  Back curves under a second name.
- **`core`** — `GameLoop` keeps a single frame chain when it is stopped and restarted from inside a
  frame handler, where it used to leave two frames scheduled, and it reuses one frame callback
  instead of creating a closure per frame.
- **`animation`** — `spring()` throws a `RangeError` naming the field for a `mass` not above 0, a
  negative `stiffness` or `damping`, or a non-finite field. These configs used to produce `NaN` or
  a runaway value.
- **`assets`** — `parseAseprite` names the frames of an Aseprite hash export after their keys, so
  `getFrame` and `frameMap` resolve them. Every frame name used to be `undefined`.
- **`audio`** — `Music.stop()` and `Music.play()` during a crossfade stop the fading-out track at
  once, where it used to stay audible for up to the crossfade duration.
- **`scene`** — `push()` and `pop()` while an animated `go()` is still fading out are ignored, with a
  one-time dev warning. They used to enter or destroy the pending scene out of order.
- **`haptics`** — `createExpoHapticsProvider(Haptics, { platform: Platform.OS })` plays Android
  system haptic effects through expo's optional `performAndroidHapticsAsync`. If the module rejects
  an effect, that cue falls back to the original vibrator call and the effect is not tried again.
  Other platforms, and calls without the option, behave as before. New type

## 0.4.11

Additions, fixes and internal refactors in 17 packages. The other 25 change only their version.

- **`progression`** — `createGameClock(config, state?)` is a 1440-minute game-day clock whose
  ordered segments each run at their own real-seconds-per-game-hour rate. `update(dt)` lands exactly
  on every boundary it crosses. `advanceMinutes` and `skipTo` move it in game minutes, `pause` and
  `resume` stop and restart it, and `hold` stops it at the next phase boundary until `release`. It
  has `onSegmentChange` and `onPhaseChange` callbacks, and a plain `serialize()` state restores
  through the second argument.
- **`animation`** — `updateSpring` advances with the exact damped-oscillator solution instead of one
  semi-implicit Euler step of the whole `dt`. A clamped 0.25 s hitch frame no longer blows a default
  spring up, and n steps of `dt` equal one step of n·`dt`. Trajectories at ordinary frame rates
  differ slightly from the old steps; settle thresholds and `atRest` are unchanged. `tween()` without
  an `easing` now defaults to `linear` from `@flare-engine/math`, so
  `tween(0, 1, 1).easing === linear` holds. Values are unchanged.
- **`create`** — the `blank`, `topdown` and `shmup` templates move from Expo SDK 57 to Expo SDK 58:
  React Native 0.88.1, React 19.3.0, `@shopify/react-native-skia` 2.14.0, and Reanimated 4.7.1 with
  worklets 0.13.0. `canvaskit-wasm` stays at 0.41.0, the version RN-Skia 2.14.0 pins.
- **`scene`** — a `go()` issued while an animated `go()` is still fading out now destroys the
  superseded target (`onDestroy`, never `onInit` or `onEnter`) and drops it from the cache, so a
  later `push()` or `go()` of that name builds a fresh instance. `destroy()` does the same to a
  pending target. An instant `go()` ends any transition in progress, so a stale target can no longer
  replace the new scene.
- **`dialogue`** — `updateTextReveal` treats `punctuationDelay` as extra time, so the gap after a
  `.!?:;` is `1 / speed + punctuationDelay`, as documented. Before, `punctuationDelay` replaced the
  gap: the extra delay was about 0.117 s instead of 0.15 s at the default 30 cps, and text slower
  than about 6.7 cps sped up after punctuation. `updateTextReveal` also no longer rebuilds
  `visibleText` while the revealed count is unchanged, so a caller that overwrites `visibleText` with
  a string of the same length keeps it until the count changes. The `ActionHandler` JSDoc now states
  that the runner does not await a returned promise.
- **`ui`** — `Button` no longer unregisters and re-registers its focus node when a parent re-render
  passes a new `onPress` identity or changes `disabled` or `tabIndex`, so keyboard focus and tab
  order survive re-renders. `FocusManager.register` of an already-registered id updates that node in
  place, `activate()` skips a disabled focused node, and the disposer that `register` returns works
  destructured.
- **`share`** — `createNativeShareTransport` passes a `screenshot` to RN `Share` as a `data:` URL
  when the payload sets no `url`, so iOS attaches the image; an explicit `url` still wins. On
  Android, where RN's `Share` forwards only `title` and `message`, a screenshot-only payload now
  opens an empty sheet that reports `dispatched: true` instead of rejecting.
- **`achievements`, `storage`** — `createStorageAchievements` no longer caches a failed hydration:
  when `store.get` rejects, that call rejects and the next call reads again. `createIndexedDbAdapter`
  likewise retries a failed `indexedDB.open`. `createStorage` no longer writes a `__flare_version`
  key on `saveSlot`, and `createDocumentStore` no longer writes `__flare_doc_version`. Nothing read
  either key, and keys already in a store are left in place.
- **`debug`** — with `new DebugOverlay({ reuseCommands: true })`, `drawRect`, `drawCircle` and
  `drawLine` reuse pooled command objects, which change after `clear()`. Without the option every
  call still creates a fresh object. `createFrameBudget` keeps a running fps sum instead of
  re-summing its ring on every `recordFrame`. After a non-finite `dt`, `getAvgFps()` reads 0 for
  under two ring lengths, where it was one before.
- **`pathfinding`** — `findPath` and `findPathJPS` keep their search scratch per `Grid` and reuse it,
  so a repeat search allocates no typed arrays unless its open set outgrows the kept heap.
  `findPathJPS` scans jumps in a loop, so a long open corridor no longer overflows the stack on V8
  and Hermes. `findNavMeshPath` keeps a per-mesh id index and computes each centroid at most once per
  search. Results are unchanged.
- **Internal refactors, no behaviour or API change** — `audio` (`Music` track start), `create`
  (`--template` parsing), `engine` (the main entry re-exports `@flare-engine/engine/headless`; the
  exported names are unchanged), `errors` (one payload-to-`Error` helper for both transports), `iap`
  (`getGrantsForProduct`), `progression` (`resolveTier`), `scene` (stack teardown), `shapes` (one
  fill-then-stroke helper), `simulation` (`NBodySystem.step` calls `verletStep`) and
  `storage` (one envelope guard).

Fixes in `@flare-engine/tilemap`, `react`, `render-web` and `errors`. The other 38 packages change

## Conventions

- **Lockstep.** Never bump a single package. A release moves every `@flare-engine/*` together.
- **Never a major.** A major on any package would force the whole lockstep set to 1.0.0.
- Releases are cut with Changesets; see [`AGENTS.md`](AGENTS.md) for the commit and versioning
  contract.
